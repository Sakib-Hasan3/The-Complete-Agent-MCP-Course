# LLM as a Judge: Rank Multiple LLMs with an Orchestration Flow

এই lesson-এ আমরা শিখব কীভাবে একাধিক LLM-এর উত্তর অন্য একটি LLM দিয়ে evaluate করানো যায় এবং তাদের performance অনুযায়ী ranking তৈরি করা যায়।

এটিকে বলা হয় LLM-as-a-Judge।

তুমি আগের lesson-এ শিখেছ কীভাবে একই প্রশ্ন GPT, Claude, Gemini বা Ollama-এর model-কে পাঠাতে হয়। এবার সেই উত্তরগুলো একজন AI Judge দিয়ে যাচাই করব।

এখানে GPT, Claude ও Gemini হলো Candidate Models। আর Judge হলো একটি আলাদা model, যার কাজ candidate-দের উত্তর মূল্যায়ন করা।

সহজ উদাহরণ: তিনজন শিক্ষার্থী একটি প্রশ্নের উত্তর লিখেছে। একজন শিক্ষক তাদের উত্তর পড়ে নম্বর দিলেন। এখানে শিক্ষার্থীরা হলো Candidate LLM এবং শিক্ষক হলো Judge LLM।

## ২. Judge কী কী বিষয় বিবেচনা করবে?

শুধু সুন্দর ভাষায় উত্তর দিলেই একটি model সেরা হয় না। আমরা কয়েকটি criterion ব্যবহার করব।

| Criterion             | কী যাচাই করবে?                 | Score |
| --------------------- | ------------------------------ | ----- |
| Accuracy              | উত্তর সঠিক কি না               | 1–10  |
| Relevance             | প্রশ্নের সঙ্গে সম্পর্কিত কি না | 1–10  |
| Completeness          | প্রয়োজনীয় বিষয়গুলো আছে কি না   | 1–10  |
| Clarity               | সহজে বোঝা যায় কি না            | 1–10  |
| Instruction Following | নির্দেশনা মেনেছে কি না         | 1–10  |

ধরো, Judge এভাবে score দিল:

| Model  | Accuracy | Relevance | Completeness | Clarity | Total |
| ------ | -------- | --------- | ------------ | ------- | ----- |
| GPT    | 9        | 9         | 8            | 9       | 35    |
| Claude | 9        | 9         | 9            | 8       | 35    |
| Gemini | 8        | 8         | 8            | 9       | 33    |

এখানে GPT ও Claude-এর score সমান। তাই শুধু total score দেখে winner নির্ধারণ না করে tie-break rule ব্যবহার করতে পারো, অথবা তাদের উত্তর আবার তুলনা করতে পারো।

## ৩. Orchestration Flow কী?

Orchestration মানে হলো একাধিক AI model ও workflow step-কে একটি নির্দিষ্ট পরিকল্পনা অনুযায়ী পরিচালনা করা।

আমাদের কাজের flow হবে:

1. User একটি প্রশ্ন দেবে।
2. প্রশ্নটি একাধিক Candidate LLM-এ পাঠানো হবে।
3. সব model-এর উত্তর সংগ্রহ করা হবে।
4. উত্তরগুলো Judge LLM-এর কাছে পাঠানো হবে।
5. Judge প্রত্যেক উত্তরকে নির্দিষ্ট criteria অনুযায়ী score দেবে।
6. Score অনুযায়ী ranking তৈরি হবে।
7. Final result দেখানো হবে।

## ৪. Python দিয়ে একটি simple LLM Judge তৈরি

আমরা আগের lesson-এর OpenAI-compatible API ধারণা ব্যবহার করব। এখানে উদাহরণ হিসেবে Groq-কে Judge হিসেবে ব্যবহার করা হচ্ছে, আর candidate responses আপাতত sample data।

প্রথমে `.env` file-এ যোগ করো:

```
GROQ_API_KEY=your_groq_api_key
```

তারপর `judge.py` তৈরি করো।

```
import osimport jsonfrom openai import OpenAIfrom dotenv import load_dotenvload_dotenv()# Judge model clientjudge = OpenAI(    api_key=os.getenv("GROQ_API_KEY"),    base_url="https://api.groq.com/openai/v1")# Candidate LLM responsesquestion = "What is an AI Agent?"answers = {    "GPT": "An AI Agent is a system that observes its environment, makes decisions, and takes actions to achieve a goal.",    "Claude": "An AI Agent is an AI-powered system that can reason, use tools, and perform actions to complete tasks.",    "Gemini": "An AI Agent is a software system that uses AI to understand tasks and perform actions with some autonomy."}# Evaluation instructionsprompt = f"""You are an impartial AI evaluator.Question: {question}Evaluate these answers:{json.dumps(answers, indent=2)}Give each answer a score from 1 to 10 for:1. Accuracy2. Relevance3. Completeness
```

Code-এর গুরুত্বপূর্ণ অংশগুলো:

- `answers`: বিভিন্ন model-এর উত্তর সংরক্ষণ করছে।
- `prompt`: Judge-কে evaluation criteria বুঝিয়ে দিচ্ছে।
- `temperature=0`: scoring-এ অপ্রয়োজনীয় randomness কমাতে সাহায্য করে।
- `json.loads()`: Judge-এর JSON output-কে Python dictionary-তে রূপান্তর করছে।
- `ranking`: Judge-এর দেওয়া ranking দেখাচ্ছে।

এই উদাহরণে candidate responses hardcoded। বাস্তব project-এ আগের lesson-এর মতো API call করে GPT, Claude ও Gemini-এর উত্তর এখানে যোগ করবে।

নোট: Groq-এর model availability পরিবর্তিত হতে পারে। `llama-3.3-70b-versatile` তোমার account-এ available না থাকলে Groq Console-এর বর্তমান supported model ID ব্যবহার করবে। JSON parsing ব্যর্থ হলে structured output validation ও retry যোগ করতে হবে।

## ৫. n8n-এ কীভাবে বানাবে?

এই workflow-টি n8n-এ নিচের nodes দিয়ে তৈরি করতে পারো।

| Step | n8n Node                | কাজ                      |
| ---- | ----------------------- | ------------------------ |
| 1    | Manual Trigger          | Evaluation শুরু          |
| 2    | Edit Fields             | Question তৈরি            |
| 3    | HTTP Request / LLM Node | GPT call                 |
| 4    | HTTP Request / LLM Node | Claude call              |
| 5    | HTTP Request / LLM Node | Gemini call              |
| 6    | Merge                   | তিনটি response একত্র করা |
| 7    | HTTP Request / LLM Node | Judge-কে পাঠানো          |
| 8    | Code                    | Score অনুযায়ী sort       |
| 9    | Output                  | Ranking দেখানো           |

তুমি চাইলে GPT, Claude ও Gemini-এর জন্য আলাদা HTTP Request node ব্যবহার করতে পারো। Judge হিসেবে Groq বা অন্য কোনো provider-এর model ব্যবহার করা যাবে।

## ৬. LLM Judge-এর সীমাবদ্ধতা

LLM Judge সবসময় সঠিক বিচারক নয়। এর কিছু সমস্যা আছে:

1\. Position Bias

প্রথমে থাকা উত্তরকে বেশি ভালো মনে করতে পারে।

2\. Verbosity Bias

বড় ও বিস্তারিত উত্তরকে অযথা বেশি score দিতে পারে।

3\. Self-preference Bias

নিজের model family-এর উত্তরকে বেশি পছন্দ করতে পারে।

4\. Hallucination

Judge নিজেও ভুলভাবে score দিতে পারে।

5\. Prompt Injection

কোনো candidate answer-এর মধ্যে Judge-কে প্রভাবিত করার instruction থাকতে পারে।

### Bias কমানোর উপায়

- Candidate model-এর নাম লুকিয়ে `Answer A`, `Answer B`, `Answer C` ব্যবহার করো।
- উত্তরগুলোর ক্রম পরিবর্তন করে একাধিকবার evaluation করো।
- একই rubric ব্যবহার করো।
- High-stakes evaluation হলে human review রাখো।
- সম্ভব হলে একাধিক Judge ব্যবহার করে score aggregate করো।
- Factual task-এর ক্ষেত্রে reference answer বা verified facts-এর সঙ্গে মিলিয়ে দেখো।

গুরুত্বপূর্ণ: LLM Judge-এর ranking-কে চূড়ান্ত সত্য হিসেবে ধরবে না। এটি একটি evaluation signal, definitive benchmark নয়।

## ৭. আরও ভালো Evaluation: Weighted Scoring

সব criteria-র গুরুত্ব সমান নাও হতে পারে।

উদাহরণস্বরূপ:

| Criterion    | Weight |
| ------------ | ------ |
| Accuracy     | 40%    |
| Relevance    | 25%    |
| Completeness | 20%    |
| Clarity      | 15%    |

তাহলে:

\\[ Score = 0.4A+0.25R+0.2C+0.15L \\]

যেখানে A = Accuracy, R = Relevance, C = Completeness এবং L = Clarity।

ধরো, একটি model পেয়েছে:

- Accuracy = 9
- Relevance = 8
- Completeness = 7
- Clarity = 9

তাহলে:

\\[ Score=0.4(9)+0.25(8)+0.2(7)+0.15(9)=8.35 \\]

Final score: 8.35/10

## ৮. তোমার Bangla Handwriting VLM Research-এ এর ব্যবহার

তোমার Bangla handwritten answer transcription research-এ এই পদ্ধতি কাজে লাগতে পারে।

ধরো, একই handwriting image থেকে তিনটি model transcription তৈরি করল:

- Model A: Fine-tuned Qwen
- Model B: Gemini
- Model C: অন্য একটি VLM

এখানে শুধু LLM Judge দিয়ে winner নির্বাচন করবে না। বরং:

1. Ground-truth transcription-এর সঙ্গে CER ও WER হিসাব করবে।
2. Character omission, insertion ও substitution পরীক্ষা করবে।
3. Judge দিয়ে readability ও instruction-following evaluate করতে পারো।
4. Human reviewer দিয়ে difficult cases যাচাই করবে।

এভাবে automatic metric, LLM Judge এবং human evaluation একত্র করলে research-এর evaluation অনেক বেশি শক্তিশালী হবে।
