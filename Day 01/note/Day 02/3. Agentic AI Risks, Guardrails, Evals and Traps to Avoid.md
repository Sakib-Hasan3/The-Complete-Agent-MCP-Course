# Agentic AI: Risks, Guardrails, Evals and Traps to Avoid

এই টপিকটি AI Engineering শেখার জন্য খুবই গুরুত্বপূর্ণ। কারণ শুধু AI Agent তৈরি করতে পারলেই হবে না—এটি যেন ভুল সিদ্ধান্ত না নেয়, অনিরাপদ কাজ না করে এবং নির্ভরযোগ্য ফলাফল দেয়, সেটিও নিশ্চিত করতে হবে।

আজ আমরা ৪টি বিষয় একদম সহজ বাংলায় শিখব:

1. Risks — AI Agent-এর ঝুঁকি কী কী?
2. Guardrails — Agent-কে নিরাপদ রাখবে কীভাবে?
3. Evals — Agent ঠিকমতো কাজ করছে কি না, তা পরীক্ষা করবে কীভাবে?
4. Traps to Avoid — Agent তৈরি করার সময় কোন ভুলগুলো এড়িয়ে চলবে?

## 1. Risks — AI Agent-এর ঝুঁকি

একটি সাধারণ Chatbot ভুল উত্তর দিতে পারে। কিন্তু একটি AI Agent-এর কাছে যদি Tools ব্যবহারের ক্ষমতা থাকে, তাহলে ভুল সিদ্ধান্ত নিয়ে বাস্তব কাজও করে ফেলতে পারে।

ধরো, তুমি একটি AI Email Agent তৈরি করেছ। এর কাজ হলো Email পড়া এবং উত্তর পাঠানো।

যদি Agent ভুল করে কোনো গুরুত্বপূর্ণ Email-এ ভুল উত্তর পাঠিয়ে দেয়, তাহলে সেটি শুধু ভুল তথ্য দেওয়া নয়—এটি একটি বাস্তব সমস্যা তৈরি করেছে।

Risk 1: Hallucination

AI এমন তথ্য আত্মবিশ্বাসের সঙ্গে দিতে পারে, যা ভুল বা বাস্তবে নেই।

উদাহরণ: Research Agent এমন একটি Research Paper-এর তথ্য তৈরি করল, যেটি আসলে নেই।

Agent ভুল Tool ব্যবহার করে কোনো কাজ করে ফেলতে পারে।

উদাহরণ: ভুল Email Address-এ Email পাঠানো বা ভুল Database Record পরিবর্তন করা।

Agent প্রয়োজনের অতিরিক্ত ব্যক্তিগত বা গোপন তথ্য প্রকাশ করতে পারে।

Risk 5: Infinite Loops and Excessive Costs

Agent একই কাজ বারবার করতে পারে, অপ্রয়োজনীয় API Call করতে পারে বা কাজ শেষ না করেই চলতে থাকতে পারে।

উদাহরণ: Research Agent একই Search বারবার করে API Credits শেষ করে ফেলল।

মূল কথা: AI Agent যত বেশি স্বাধীনভাবে কাজ করতে পারে, তার কাজের ওপর তত বেশি উপযুক্ত নিয়ন্ত্রণ ও পর্যবেক্ষণ দরকার।

## 2. Guardrails — AI Agent-কে নিরাপদ রাখার ব্যবস্থা

Guardrails হলো এমন নিয়ম, যাচাই এবং সীমাবদ্ধতা, যা AI Agent-কে নির্ধারিত সীমার মধ্যে কাজ করতে সাহায্য করে।

একটি সহজ উদাহরণ দেখি।

ধরো, তোমার AI Agent Email Draft তৈরি করতে পারবে, কিন্তু তোমার অনুমতি ছাড়া Email পাঠাতে পারবে না।

এখানে Email পাঠানোর আগে Approval নেওয়া একটি Guardrail।

AI Agent

Email Draft তৈরি করে

Guardrail Check

Recipient, Content এবং Permission যাচাই

Approved

অনুমতি পেলে পাঠানো

Blocked

অনুমতি না থাকলে পাঠানো বন্ধ

### গুরুত্বপূর্ণ Guardrails

| Guardrail              | কাজ                                                       |
| ---------------------- | --------------------------------------------------------- |
| Input Validation       | User Input সঠিক Format-এর কি না যাচাই                     |
| Output Validation      | AI-এর Output নির্দিষ্ট নিয়ম মেনে তৈরি হয়েছে কি না পরীক্ষা |
| Tool Permissions       | Agent কোন Tool ব্যবহার করতে পারবে তা সীমিত করা            |
| Human Approval         | গুরুত্বপূর্ণ কাজের আগে মানুষের অনুমতি নেওয়া               |
| Rate Limits            | API Call বা Action-এর সংখ্যা সীমিত করা                    |
| Data Access Control    | Agent-কে প্রয়োজনীয় Data-তেই Access দেওয়া                  |
| Logging and Monitoring | Agent কী করেছে, তা Record ও Monitor করা                   |

### Least Privilege কী?

এটি একটি গুরুত্বপূর্ণ Security Principle।

এর অর্থ হলো, Agent-কে শুধু সেই Permission দেওয়া, যা তার কাজ সম্পন্ন করার জন্য প্রয়োজন।

যেমন:

- Email Summarize করতে হলে Email Read Permission যথেষ্ট হতে পারে।
- Email পাঠানোর প্রয়োজন না থাকলে Send Permission দেবে না।
- Database থেকে তথ্য পড়ার দরকার হলে Delete Permission দেবে না।

মনে রাখবে: Prompt-এ “ভুল করবে না” লিখে দিলেই Agent নিরাপদ হয়ে যায় না। গুরুত্বপূর্ণ নিরাপত্তা অবশ্যই Tool Permission, Validation এবং System-Level Control দিয়ে নিশ্চিত করতে হবে।

## 3. Evals — AI Agent ঠিকমতো কাজ করছে কি না পরীক্ষা

Evals বা Evaluations হলো নির্দিষ্ট Test Case ও Metrics ব্যবহার করে AI System-এর Performance এবং Reliability মূল্যায়ন করার প্রক্রিয়া।

যেমন, তুমি একটি Research Assistant তৈরি করলে। এটি Research Paper খুঁজে Summary তৈরি করতে পারে।

এখন কীভাবে বুঝবে এটি ভালো কাজ করছে?

শুধু একটি ভালো Summary দেখে সিদ্ধান্ত নেওয়া যাবে না। বিভিন্ন ধরনের Input দিয়ে পরীক্ষা করতে হবে।

## Research Agent Evaluation Example

Test 1: Search Accuracy

Agent কি সত্যিকারের Research Paper খুঁজে পেয়েছে? Source Link কি সঠিক?

Test 2: Summary Quality

Summary কি Paper-এর মূল বক্তব্য ঠিকভাবে তুলে ধরেছে, নাকি গুরুত্বপূর্ণ তথ্য বাদ পড়েছে?

Test 3: Safety

ক্ষতিকর নির্দেশনা দেওয়া হলে Agent কি সেটি অনুসরণ না করে নিরাপদে কাজ করতে পেরেছে?

Test 4: Cost and Latency

কাজটি করতে কত সময় লেগেছে? কতটি API Call হয়েছে? খরচ কত?

### কোন কোন Metric ব্যবহার করা যায়?

| Metric                | কী পরিমাপ করে                                         |
| --------------------- | ----------------------------------------------------- |
| Accuracy              | উত্তর বা Classification কতটা সঠিক                     |
| Task Success Rate     | কত শতাংশ ক্ষেত্রে কাজ সফলভাবে সম্পন্ন হয়েছে           |
| Tool Call Accuracy    | সঠিক Tool এবং সঠিক Arguments ব্যবহার হয়েছে কি না      |
| Groundedness          | উত্তরটি নির্ভরযোগ্য Source-এর তথ্যের সঙ্গে মেলে কি না |
| Latency               | উত্তর পেতে কত সময় লাগে                                |
| Cost per Task         | প্রতিটি কাজ সম্পন্ন করতে কত খরচ হয়                    |
| Safety Violation Rate | কতবার নিরাপত্তার নিয়ম ভঙ্গ হয়েছে                      |

সব Metric সব Agent-এর জন্য প্রযোজ্য নয়। তোমার Agent-এর কাজ অনুযায়ী Metric বেছে নিতে হবে।

### Evals কীভাবে করবে?

1. কিছু বাস্তবসম্মত Test Case তৈরি করো।
2. প্রতিটি Test Case-এর Expected Result নির্ধারণ করো।
3. Agent চালিয়ে Output সংগ্রহ করো।
4. Output-কে Expected Result-এর সঙ্গে তুলনা করো।
5. ভুলের ধরন শনাক্ত করো।
6. Prompt, Tool, Model বা Guardrail উন্নত করে আবার Test করো।

এই প্রক্রিয়াটি বারবার করতে হবে। একবার Test পাস করলেই Agent সব পরিস্থিতিতে নির্ভরযোগ্য হবে, এমন নয়।

## 4. Traps to Avoid — যে ভুলগুলো এড়িয়ে চলবে

AI Agent তৈরি করতে গিয়ে নতুন Developer-রা কিছু সাধারণ ভুল করে থাকে।

Trap 1: সব কাজের জন্য AI Agent ব্যবহার করা

যদি কাজটি সাধারণ IF/ELSE বা নির্দিষ্ট Workflow দিয়ে নির্ভরযোগ্যভাবে করা যায়, তাহলে শুধু AI Agent যোগ করার দরকার নেই।

সমাধান: আগে সবচেয়ে সহজ এবং নির্ভরযোগ্য Design বেছে নাও।

Trap 2: অতিরিক্ত Permission দেওয়া

Agent-কে সব API, Database এবং Email-এর Full Access দিয়ে দেওয়া বিপজ্জনক।

সমাধান: Least Privilege অনুসরণ করো এবং গুরুত্বপূর্ণ কাজের আগে Approval রাখো।

Trap 3: শুধু ভালো Output দিয়ে পরীক্ষা করা

দুই-একটি সফল Demo দেখে Agent-কে Production-এ ব্যবহার করা ঠিক নয়।

সমাধান: ভুল Input, Missing Data, API Failure এবং Prompt Injection-সহ বিভিন্ন পরিস্থিতিতে Test করো।

Trap 4: Agent-কে অনির্দিষ্টভাবে চলতে দেওয়া

Agent একই Tool বারবার ব্যবহার করতে পারে বা সমস্যার সমাধান না করেই চালিয়ে যেতে পারে।

সমাধান: Maximum Iterations, Timeout, Rate Limit এবং Budget Limit নির্ধারণ করো।

Trap 5: Prompt-কে Security System মনে করা

শুধু System Prompt দিয়ে সব আক্রমণ ঠেকানো সম্ভব নয়।

সমাধান: Permission Control, Input/Output Validation, Tool Restrictions এবং Human Approval ব্যবহার করো।

Trap 6: Error Handling না রাখা

API বন্ধ থাকলে বা Model ভুল Format দিলে পুরো Workflow ব্যর্থ হতে পারে।

সমাধান: Error Handling, Retry Policy, Logging এবং প্রয়োজনে Human Escalation যোগ করো। Retry যেন একই Action অনিচ্ছাকৃতভাবে একাধিকবার সম্পন্ন না করে, সেটিও নিশ্চিত করো।

## 5. সবকিছু একসঙ্গে: একটি নিরাপদ AI Agent Architecture

ধরো, তুমি n8n দিয়ে একটি AI Customer Support Agent তৈরি করছ।

1\. User Input

Customer-এর প্রশ্ন

2\. Input Guardrails

Validation এবং Security Checks

3\. AI Agent

প্রশ্ন বোঝে এবং প্রয়োজনীয় Tool নির্বাচন করে

4\. Tool Permission + Execution Limits

অনুমোদিত Action, Rate Limit এবং Timeout

5\. Output Validation

উত্তর ও Action যাচাই; প্রয়োজন হলে Human Approval

6\. Response + Logs

উত্তর প্রদান এবং পরবর্তী Evaluation-এর জন্য তথ্য সংরক্ষণ

এখানে Logs এবং Monitoring পুরো Workflow জুড়ে কাজ করবে। পরে সেই Logs ব্যবহার করে Evals চালানো ও সমস্যা শনাক্ত করা যাবে।


## শেষ কথা

একজন ভালো AI Engineer শুধু এমন Agent তৈরি করেন না, যেটি কাজ করতে পারে। তিনি এমন Agent তৈরি করেন, যেটি সঠিকভাবে কাজ করে, সীমাবদ্ধতা মেনে চলে, ভুল হলে তা শনাক্ত করা যায় এবং পরীক্ষা করে তার নির্ভরযোগ্যতা বাড়ানো যায়।
